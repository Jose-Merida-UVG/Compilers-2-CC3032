# Compiscript — Análisis Léxico, Sintáctico y Semántico

**Demo (Lab 1 — léxico/sintáctico):** https://youtu.be/IowDshTJ0TI

Compilador (front-end) de Compiscript, un lenguaje pequeño similar a un
subconjunto de TypeScript (`let`/`const`/`var`, anotaciones `: type`,
funciones, clases con herencia, arreglos, control de flujo, etc. — ver
`src/grammar/Compiscript.g4` para la gramática exacta). Cubre las tres
fases del **Proyecto 1**: léxico y sintáctico (ANTLR4) y semántico
(sistema de tipos, tabla de símbolos con manejo de ámbitos, visitor sobre
el árbol de parseo). Todo el código del compilador vive en `src/`;
`frontend/` es el IDE de navegador (React) que sirve de interfaz gráfica.

Ver [docs/plan-proyecto1.md](docs/plan-proyecto1.md) para la división de
trabajo del equipo y decisiones de diseño, y
[docs/ModuloAmbito.md](docs/ModuloAmbito.md) /
[docs/ModuloTiposFunciones.md](docs/ModuloTiposFunciones.md) para la
documentación de arquitectura de la tabla de símbolos y del sistema de
tipos+funciones respectivamente.

## Project structure

- `src/grammar/Compiscript.g4` — ANTLR4 grammar (source of truth for lexer/parser rules).
- `src/generated/` — build output regenerated by `make generate`; never edited by hand.
- `src/compiler.py` — shared pipeline (lex + parse + semantic check + error collection) used by both the CLI and the server.
- `src/error_listener.py` — custom ANTLR error listener that formats lexical/syntax errors in Spanish, with error recovery (keeps going after the first error).
- `src/semantic/` — semantic analysis: `types.py` (type system), `symbols.py` (symbol table + scope tree), `errors.py`, `checker.py` (the `SemanticChecker` ANTLR visitor implementing every rule).
- `src/main.py` — CLI entrypoint (`make cli`).
- `src/server.py` — FastAPI backend: file-CRUD API over `workspace/` plus `/api/run`.
- `src/tests/` — automated test suite (`make test`), including `src/tests/semantic/<categoria>/` with one battery of `.cps` cases per semantic rule category.
- `src/tools/` — vendored ANTLR jar used only for code generation.
- `frontend/` — browser IDE (Vite + React/TS): file explorer (selecciona el archivo de entrada), editor, panel de salida, visor de árbol de parseo, y visor de tabla de símbolos — todos los resultados del análisis se muestran ahí, no solo en consola.
- `workspace/` — the IDE's working directory: `input/` has sample `.cps` programs, `output/` has persisted run results (`.out`/`.tree`).
- `docs/` — documentación de arquitectura y de la definición del lenguaje.

## Requirements

- Java (JRE 11+) — only needed to run the ANTLR tool jar for code generation
- Python 3.8+
- Node.js — only needed for the frontend

## Install

```
make install
```

This creates a `.venv` at the repo root (if one doesn't already exist),
installs the Python dependencies from `src/requirements.txt` into it, and
runs `npm install` in `frontend/`.

Every Python-facing Makefile target (`run`, `cli`) auto-detects `.venv`:
if `.venv/bin/python3` / `.venv/bin/uvicorn` exist it uses those, otherwise
it falls back to whatever `python3`/`uvicorn` are on your `PATH`. You never
need to `source .venv/bin/activate` yourself — `make` handles it — but you
can if you want a shell with the venv active for e.g. running `python3`
ad-hoc.

The ANTLR tool jar is already vendored at `src/tools/antlr-4.13.2-complete.jar`
(used only for regenerating the parser, not at runtime).

## Generating the parser

Run this after any change to `src/grammar/Compiscript.g4`:

```
make generate
```

This runs `src/generate.sh`, which invokes the ANTLR jar and regenerates
`CompiscriptLexer.py`, `CompiscriptParser.py`, `CompiscriptVisitor.py`, and
`CompiscriptListener.py` into `src/generated/`. Files in `src/generated/`
are build output — never edit them by hand, edit the grammar and regenerate.

## Running a single file (CLI)

```
make cli FILE=<path-to-source-file>
```

e.g.:

```
make cli FILE=workspace/input/comp-baja/baja-val.cps
```

This lexes, parses, and (if there were no lexical/syntax errors) runs
semantic analysis on the file, printing every error found — in Spanish,
all in one run, not just the first — followed by a status line summarizing
the result.

## Running the tests

```
make test
```

Runs the full `pytest` suite: `src/tests/semantic/<categoria>/` has one
battery of `valido_*.cps`/`invalido_*.cps` cases per semantic rule
category (`tipos`, `ambito`, `funciones`, `control_flujo`, `clases`,
`arreglos`, `generales`), plus `src/tests/test_smoke.py` for
grammar/pipeline regressions. Narrow it down with e.g.
`make test ARGS="src/tests/semantic/clases -v"`.

## Web IDE (frontend + backend together)

```
make run
```

This starts both the FastAPI backend (`src/server.py`, port 8080, with
`--reload`) and the Vite frontend dev server together, and stops both on
Ctrl+C. Open the printed Vite URL (default `http://localhost:5173`) — it
proxies `/api/*` to the backend (see `frontend/vite.config.ts`).

The backend serves a small file-CRUD API over `workspace/` (repo root,
pre-seeded with sample `.cps` programs under `workspace/input/`) plus
`/api/run`, which runs a file through the same pipeline as the CLI
(`src/compiler.py`, shared by both entrypoints) and returns the errors, a
status message, a JSON parse tree, and (when semantic analysis ran) a JSON
symbol table for the viewers.

In the IDE: **select the input file from the sidebar explorer** (or create
a new one with the ＋ button) and click **▶ Run**. Every result is shown
inside the interface, not just the terminal:
- Errors (lexical, syntax, and semantic — all of them found in that run,
  not just the first) and the status line print to the output panel.
- A **parse tree** tab opens automatically, with a collapsible visual
  representation of the syntax tree.
- A **symbol table** tab opens automatically when semantic analysis ran,
  showing every scope (global, function, class, block) nested as it was
  created, each with its declared symbols, kinds, and types.

Each run also persists `output/<filename>/<filename>.out` (plain-text) and
`output/<filename>/<filename>.tree` (JSON parse tree) into the workspace —
both reopenable from the sidebar afterwards.

## Cleaning up

```
make clean       # removes __pycache__ dirs and workspace/output/
make distclean    # clean, plus removes .venv
```
